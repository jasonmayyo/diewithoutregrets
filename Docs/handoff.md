- Documents are split into at most eight sections with four concurrent provider calls. Paragraph overflow merges into the last section instead of dropping the end of the source. Results interleave sections before the card cap so later sections survive.
- Both document and topic generation screen and deduplicate cards. The client decodes cards individually, checks the answer/choice invariant, and keeps a usable partial deck even if one object is malformed.
- Responses include section coverage. Generation shows the actual saved card count and identifies incomplete coverage. There is no simulated percentage or premature automatic dismissal.
- Cancelling generation cancels the client task and prevents late saving. Failures retain the user's text. Saving reads the current deck so edits are preserved and deleted decks are not resurrected.
- App Attest requests are serialized across generation, script loading, and tutor questions. Proven invalid device keys or server `key_not_registered` responses recover once; expired generation challenges retry once using the same key; expired enrollment starts with a fresh key. Timeouts, uncertain failures, invalid assertions, and quota errors never replay paid work automatically.
- Capacity, temporary load, verification, and timeout errors have distinct handling. Provider logging contains status/counts only.
- A monster session opens and asks its first question immediately from local script banks. Optional live voice loads in the background. Saved cards that cannot be answered are skipped without modifying the deck. Reward copy uses local calculations and the actual grant.
- `Ask about this card` opens a separate question composer for any displayed card. Questions and the last four successful follow-ups on that card go to authenticated `/v1/tutor`. They never grade, advance the question, or award time.
- Tutor replies have a 20-second UI deadline. Offline/failed requests show a clear fallback with the saved card explanation when available. Closing the chat cancels pending work; late responses cannot enter a later conversation. Returning to answers preserves the current question.
- `/v1/tutor` shares the existing script quotas and 500-token output cap. No new budget bucket or quota increase was introduced in this pass.
